# 演示脚本

一场约 20 分钟的口播稿。每个场景先说"这一段展示什么"，再按表格一步步点：**点什么 → 屏幕上会看到 → 你说什么**。界面是英文的，下面所有按钮名都和屏幕上一字不差，用粗体标出。

---

## 开场前 1 分钟

1. 终端运行 `pnpm start`，等日志出现 "✔ Durable Jev demo is ready"，浏览器自动打开 <http://localhost:4100>。
2. 右上角点 **Reset demo**，所有案例回到初始状态。
3. 左上 **Playback speed** 选第二个图标 ▶▶（中速）。四个图标从左到右是慢、中、快、实时；选实时（⚡）不放动画。

界面四块：左边是案例列表和 agent 列表；中间是当前案例，上面是案例头部，下面是 **Agents / Rule graph / Timeline** 三个视图；右边是当前角色的待办；右上角的角色标签是当前角色和操作人，点它弹出角色菜单，选一个就切换。

每个案例头部右上都有 **↺ Reset this case**：只把这个案例恢复到刚收到订单时，从第一条规则重新回放，其他案例不受影响。演砸了就点它。

## 场景 1｜一眼看全局（2 分钟）

**这一段展示：** 5 个 Durable Jev Agent，每个对应一块业务；它们不共享数据库，只交换规则结论。

| # | 点什么 | 屏幕上会看到 | 你说 |
|---|---|---|---|
| 1 | 左侧选 **LOG-004**，中间点 **Agents** | 5 张 agent 卡片和它们之间的箭头 | "每张卡片是一个 agent，负责一块业务：接单协调、货物合规、运输计划、商务、目的地合规。" |
| 2 | 指着卡片上的小标签（Expression / Jev / Human / Combined） | 每个 agent 的规则构成 | "150 条规则里只有 1 条是写死的代码，其余都是从政策文本生成的配置：公式、给 Jev 的问题、人工审批步骤。" |
| 3 | 指着箭头上的数字 | 例如商务 → 订单协调 "4" | "箭头表示一个 agent 用到另一个 agent 的结论，数字是用到几条。它们之间只传结论，不共享数据。" |
| 4 | 点 **Cargo assurance** 卡片 | 右侧打开 agent 名片 | "名片上写着它负责什么、要哪些人参与。" |
| 5 | 名片底部展开 **What is a Durable Agent?** | 五条特性 | 挑一句讲："进程挂了，从断的地方接着跑；等人可以等几天。" |
| 6 | 点 **Show its rule graph →** | 只显示货物合规的规则，虚线框是别的 agent 的规则 | "这是它内部的规则流程，虚线是它依赖的外部结论。" |

看不懂颜色时，鼠标移到视图标签右侧的 **Legend** 上，会展开每种颜色和标记的说明，可以直接念。

## 场景 4｜LOG-004 主线：承运商临时取消（6 分钟）

**这一段展示：** 系统里唯一由模型自己决定下一步的部分：调查助手。它自己查资料、拿规则试算备选方案，但只能提议；人确认之后订单才变。变更后只重算受影响的规则，旧的签核作废要重签。

要点三句话：**模型干活不拍板；规则替它把关；变更只重算受影响的部分，每一步可追溯。**

| # | 点什么 | 屏幕上会看到 | 你说 |
|---|---|---|---|
| 1 | 左侧选 **LOG-004**，点 **Rule graph** | 下一步栏写着合规审核员、仓库操作员各有待办 | "这是一单冷链受控药品，要两个人签字。" |
| 2 | 下一步栏里点 **Warehouse operator wen** 角色标签（直接切换角色）；右侧 CUST-MEDI-5 填 **Recipient's name** 和 **Delivery note number**，点 **Complete and submit** | 回放 CUST-MEDI-5 通过 | "诊所要求写明收货人，这是合同里计划看不出来的部分，交给人确认。" |
| 3 | 切到 **Compliance reviewer**，右侧 R13 点 **Approve** | 字幕最后停在 "R13 waits for the quality reviewer" | "审批链第一步完成，第二步要另一个人。" |
| 4 | 切到 **Quality reviewer**，R13 点 **Approve** | R13 通过，只剩装车 | "两步由不同的人签，规则里写着 Four eyes。" |
| 5 | 头部 **Demo actions** 点 **Incident: …**（主承运商 Polar 取消） | 订单和规则都没变；字幕依次显示调查助手每一步：读订单 → 查 LEG-1 的备用运力 → 预检三个方案 → 提交建议 | "现在出意外：承运商取消了。调查助手开始工作，但注意，订单一个字都没变。" |
| 6 | 看案例上方的调查卡片 | 建议改派到 OFF-FROST-0630，额外费用 $800，规则预检全绿；理由里写着另外两个为什么不行 | "它把每个备选方案拿去给规则试算，挑出全部通过里最便宜的那个，理由写得清清楚楚。" |
| 7 | 切到 **Warehouse operator** | 卡片上没有确认按钮，写着只有运输计划员能确认 | "不是谁都能拍板。" |

## 场景 5｜审批不能越权（2 分钟）

**这一段展示：** 审批规则由系统强制：错的角色签不了，同一个人签不了两步，只批一半也放不了行。

**LOG-003：商务主管不能替合规签字**

| # | 点什么 | 屏幕上会看到 | 你说 |
|---|---|---|---|
| 1 | 选 **LOG-003** | 状态 **On hold**：安全说明和货物描述对不上 | "受控货的文件对不上，直接暂停。" |
| 2 | 头部 **Demo actions** 点 **Change the order: …**（客户补交正确的安全说明） | 回放：一批结果失效后重算，出现合规签核 R13 | "客户补了文件，只重算跟文件有关的规则。" |
| 3 | 切到 **Commercial manager** | 右侧没有 R13 这张待办 | "商务主管看不到这张任务，签不了。" |
| 4 | 切到 **Compliance reviewer**，R13 点 **Approve** | R13 通过 | "必须合规审核员签。" |

**LOG-005：两个审批缺一不可，同一个人不能签两步**

| # | 点什么 | 屏幕上会看到 | 你说 |
|---|---|---|---|
| 1 | 选 **LOG-005**，点 **Change the order: …**（改派绕行，额外费用 13,000） | 出现两个审批：R34 超授信例外、R35 额外费用 | "改派后超出授信，又多了运费，这是两件独立的事。" |
| 2 | 切到 **Commercial manager**，R35 点 **Approve** | 仍然等 R34 | "只批一个，照样放不了行。" |
| 3 | R34 点 **Approve**（第 1 步） | R34 进入第 2 步 | "超过二级额度要两名商务主管。" |
| 4 | 第 2 步再点 **Approve** | 提示同一个人不能批同一审批链的两步 | "同一个人签第二次，系统拒绝。这一步要换另一位主管来签。" |

（控制台每个角色只有一位演示操作人，所以 LOG-005 演到被拒为止；完整流程由 `pnpm replay` 验证。）

## 场景 8｜LOG-006：进程挂了不丢任务（1 分钟）

**这一段展示：** agent 进程崩溃再重启，等人的任务原样回来，接着办。

| # | 点什么 | 屏幕上会看到 | 你说 |
|---|---|---|---|
| 1 | 选 **LOG-006**，右上角角色标签切到 **Technical evaluator** | 左下 agent 列表每个 agent 旁出现 **Stop** | "我现在是技术评估员，可以直接杀进程。" |
| 2 | **Cargo assurance** 旁点 **Stop** | 它变成 **Offline**；它负责的待办消失，这单也放不了行 | "货物合规 agent 挂了。" |
| 3 | 点 **Restart** | 恢复在线，质量处置 R20 和整改 R21 原样回来 | "重启后从断的地方接着跑，任务一个没丢。" |

更多故障场景在终端跑 `pnpm faults`：18 个场景，包括调查到一半、预订已写入、等人审批时真实杀进程再恢复，报告写在 `var/reports/faults.md`。

## 收尾：怎么扩展、谁来维护（30 秒）

- **加规则 = 写政策文本**：`pnpm author "Appendix G"` 让编写 agent 从政策原文生成规则，自动校验，给出 diff，人审核后合入。
- **加 agent = 配置**：目的地合规 agent 是后加的，原有 4 个 agent 一行代码没改。
- **换通信方式**：`pnpm start:a2a` 后 Agents 视图显示 "Transport: A2A"，业务结果不变。

## 演示中出状况

| 情况 | 怎么办 |
|---|---|
| 动画太慢 | 字幕右侧点 **Skip to the end** |
| 点不了某个按钮 | 先看右上角的角色对不对；被拒时右侧会用一句话说明原因和下一步 |
| 某个案例被点乱了 | 案例头部 **↺ Reset this case** |
| 全部要重来 | 右上 **Reset demo** |

真实模型（Jev、调查助手、规则编写）默认关闭，用 `MODEL_MODE=live` 打开，见 [getting-started.md](getting-started.md)。
