# 演示脚本

约 20 分钟。前 10 分钟面向业务（"以前一个大团队三年的规则引擎，现在一个小团队三个月"），后 10
分钟面向技术负责人（几个 agent、怎么协作、怎么扩展和维护）。架构说明见
[agent-architecture.md](agent-architecture.md)。

## 准备

```bash
pnpm bootstrap
pnpm start          # 或 pnpm start:a2a：agent 之间改走 A2A
```

打开 http://localhost:4100 。右上角按下表切换**角色**，操作人随角色自动切换（wen、dee、alice…），不能手改；"重置演示"恢复全部案例。
默认用脚本化模型回答（`MODEL_MODE=scripted`）；在 `.env` 里设 `MODEL_MODE=live` 并填好 `TYPESAFE_API_KEY`、`NVIDIA_API_KEY` 就用真实 Jev 与调查助手（调查一次约 12–25 秒）。

### 演示台怎么用

| 想做什么 | 怎么做 |
|---|---|
| 知道下一步该谁做什么 | 案例头部下方的"下一步"一直显示接下来的动作：点角色（带 ⇄ 的彩色标签）就切换到那个角色，点规则编号就跳到那条规则。凡是界面上出现角色的地方（规则详情的"等谁处理"、头部"正在等"、agent 名片、调查卡片、回放结尾）都可以这样点 |
| 让观众跟上发生的事 | 右上角的事件通知像游戏里的事件流一样从上往下叠，几秒后淡出；点一条可以跳到对应规则。规则图右下角的缩略图按状态着色，方便在大图里定位 |
| 让观众看出换了角色 | 每个角色有自己的颜色：顶栏下沿、角色前的圆点、操作人标签和右侧待办的上沿随角色变色；按钮与状态颜色不变 |
| 让观众看清一次操作之后发生了什么 | 左上**动画速度**选 ▶（慢）、▶▶（中）或 ▶▶▶（快）；⚡ 是实时，不放动画。之后每次提交，规则图按步骤回放：先是谁处理了哪条规则的任务，然后逐条显示重新判断的规则（发光，指向它的连线流动），最后一步说明"现在停在哪里、等谁"。底部字幕可"跳到最后" |
| 说明一个待办对应哪一步 | 右侧待办只列当前案例的任务，其他案例的待办数在下方，点一下切过去；卡片上点规则编号（如 R39），跳到规则图里这条规则并打开详情 |
| 讲清一条规则 | 规则图里点方块：右侧打开详情（政策原文、怎么检查、和其他规则的关系、本单结果）；图上高亮它的上游（它要等的规则，青色）和下游（用它结论的规则，紫色），其余变淡。点空白处取消 |
| 介绍一个 agent | 左侧 Agents 列表或 Agent 总览里点 agent：打开它的名片，底部"什么是 Durable Agent？"可展开讲解 |
| 自动排版不理想 | 直接拖动方块；浏览器会记住位置，"恢复自动排版"还原 |
| 从入口下一张新订单 | 左侧案例列表的"＋ 新订单"：以客户身份填订单，表单按样例预先填好，提交后新案例从第一条规则开始回放（见第 2 节） |
| 看某一步的细节 | 时间线里点一行展开，技术字段（指纹、编号）以浅色小字放在最后 |

## 1. 一眼看全局（Agent 总览）

选中任意案例，停在 **Agent 总览**（点任一 agent 打开它的名片）：

- 5 个 Durable Jev Agent，每个对应一个业务模块；卡片上是它负责什么、规则构成（表达式 / Jev /
  人工 / 组合）、在办案例、各角色待办。
- 连线是跨 agent 的规则依赖（"4 条依赖"）。agent 之间只通过结果协作，不共享数据库。
- 要点：150 条规则里只有 1 条是代码（R29 预订运力），32 条由 Jev 判断非结构化内容，其余是从政策
  文本生成的配置。

点击**货物合规**打开它的名片，再点"查看它的规则图"：本 agent 的规则 + 虚线框的外部依赖。

## 2. 从入口下一张订单（新订单）

前面的案例打开时已经评估完了，时间线第一条都是"收到订单"。这一节从那之前开始：演示人员扮演客户，在下单入口提交一张订单，观众看到各 agent 从零开始逐条判断。

1. 左上**动画速度**选"中"（选"实时"会直接显示结果，不放动画）。
2. 左侧案例列表点 **＋ 新订单**。
3. **① 选一个样例**：每张卡片标出货物类别和说明，例如选 LOG-002（冷链疫苗）。下面的表单按样例填好：客户与交付、货物、运输段；样例的随附文件随订单一起提交，不能改。
4. 可以改几项给观众看，例如把交接方式改成"路边交接"、调整温度要求或换承运商。右侧**订单摘要**一直可见，"改动"一栏列出相对样例改了哪些部分，"恢复样例"还原。
5. 点摘要里的**提交订单**。新案例以样例编号加 `-N` 命名（如 `LOG-002-N1`），自动打开规则图：字幕先说"订单协调 agent 收到新订单"，然后规则一条条亮起、给出结果，最后停在"现在等谁"。

要点：

- 这是完整的入口流程：订单进来，订单协调 agent 把它交给其他 agent，每个 agent 只评估自己负责的规则，彼此只交换结果。
- 新订单沿用样例的脚本化 Jev 回答（`MODEL_MODE=live` 时由真实 Jev 判断），也沿用样例的"变更资料""发生事件"演示操作，可以接着按后面的章节演示。
- 改的内容会真实影响结果：例如 LOG-002 样例改成"路边交接"，客户规则 CUST-MEDI-1（诊所不收路边交接）不通过，订单变成"暂停"，而样例本身没有这一条。"重置演示"会清掉新下的订单。

## 4. 主线：冷链受控药品改派（LOG-004）

**这一段在展示什么。** 前两步是普通的人工审批。第 3 步起模拟一个意外：已经排好的主承运商 Polar
临时取消。这时系统里**唯一由模型自己决定下一步**的部分登场：运输计划 agent 的调查助手。它自己读订单、
找备用运力、把每个备选方案拿去给规则试算（不改订单），挑出能通过全部规则的最便宜方案，写好理由提给人。
它**只能提议**：没有运输计划员确认，订单一个字都不会变。确认之后订单生成新的资料版本 r2，只有用到
路线、承运商、报价的规则需要重新判断，其余结果直接沿用，旧的签核作废要重签。

要讲的三点：模型干活但不做决定；规则替它把关（试算）；变更只重算受影响的部分，而且每一步都能追溯。

建议把**动画速度**调到"中"，下面每一步之后规则图会按步骤演示。

| 步骤 | 角色 | 操作 | 看点 |
|---|---|---|---|
| 0 | 仓库操作员 wen | LOG-004 · CUST-MEDI-5 填诊所指定收货人与送货单号 | 合同条款里计划看不出的部分交给人工确认 |
| 1 | 合规审核员 alice | 批准 LOG-004 · R13 | 两段审批链的第一步；结尾字幕显示"现在停在：R13 等质量审核员" |
| 2 | 质量审核员 bob | 批准 R13 第二步 | 两步由不同的人签（R13 详情里"四眼原则"） |
| 3 | 任意 | 头部"发生事件：主承运商 Polar 取消…" | 点完**订单和规则都不会变**。字幕依次显示调查助手的每一步：读订单 → 查 LEG-1 的备用运力 → 预检 OFF-HARBOUR-0600 → 预检 OFF-FROST-1100 → 预检 OFF-FROST-0630 → 提交建议 |

## 5. 规则多了怎么办（LOG-007）

选中 LOG-007，打开**规则图**，左上角："本单命中 8 条 · 已按目的地、客户与货物分类筛掉 100 条"。

- 108 条扩展规则来自政策附录 G（目的地进口要求，仿新西兰 MPI 进口健康标准的结构）和附录 H
  （客户合同条款），由编写 agent 从文本生成并校验。
- Jev 分类（R42）把诊断试剂归为药品，只选德国药品要求。分类拿不准时会把几组都选上，宁多勿漏：
  例如维生素软糖，真实 Jev 给出食品 0.61、药品 0.37，两组要求都会被选中（筛选样本 S02）。
- `pnpm screening`：26 份筛选样本零漏选。

## 6. 不怕宕机（技术）

| 步骤 | 角色 | 操作 |
|---|---|---|
| 1 | 技术评估员 | 左下 Agents 面板，终止"货物合规" |
| 2 | 合规审核员 | 待办里看不到货物合规的任务，相关放行也不会通过 |
| 3 | 技术评估员 | 重启货物合规；任务原样回来，继续审批 |

命令行跑 `pnpm faults`：18 个故障场景，包括调查进行到一半、预订已写入、等待人工时真实杀进程
再恢复，结果写在 `var/reports/faults.md`。

## 7. 怎么扩展、谁来维护（技术）

- **加规则 = 写政策文本**：`pnpm author "Appendix G"` 生成并校验提案（引用、参数、环、FEEL 语法、
  筛选键），给出 diff，审核后 `pnpm author --apply <proposal>`。
- **加 agent = 配置**：目的地合规 agent 是后加的。它的规则（owner 指向它）、Agent Card 上的名称与
  描述、launcher 里一行服务定义；原有 4 个 agent 没有改动。
- **换通信方式**：`pnpm start:a2a` 后总览显示"通信：A2A"和每个 agent 处理的 A2A 任务数，业务结果
  不变。
- 控制点与证据：[runtime-controls.md](runtime-controls.md)。
